# Working together: Claude and Codex

Two coding agents work on Turfcut: Claude (Claude Code) and Codex. Astra
reviews design. Caden decides and merges. This file is how the agents share
the work without colliding.

## Rules

**`CLAUDE.md` binds both agents.** Read all of it, including the working
agreements and "Notes for future sessions". It is not only for Claude. If
anything here seems to differ from `CLAUDE.md`, `CLAUDE.md` wins.

On top of it, these collaboration rules apply to both agents:

- Caden merges and deploys. No agent merges, approves its own PR or deploys.
- Fixtures and test data go into local databases only, never the live Supabase
  project.
- Nothing invented: no made-up stats, features, results or test outcomes.
- Never disable TLS verification.

## Claiming work

The agent work board is GitHub issue
[#128 "Agent work board"](https://github.com/whiterican/TurfCut/issues/128).
If it is missing or closed, stop and ask Caden. Don't start unclaimed work.

1. Check the board to make sure nobody already holds the slice.
2. Claim it with a comment: `**Claude:** taking <slice>, branch <name>` (or
   `**Codex:** …`). The first claim wins. If two claims cross, the later one
   picks something else.
3. When the PR opens, link it on the board. When it merges or is closed, the
   owner says so on the board.
4. To give a slice up, comment `**<Agent>:** releasing <slice>`. A claim with no
   commit or comment for 48 hours may be released by Caden.

Hold one slice at a time, so the other agent always has work to take.

## Checkouts, branches and files

- **Each agent works in its own checkout**, a separate clone or a worktree
  such as `git worktree add ../TurfCut-codex -b <branch> origin/master`.
  Never switch branches in a tree the other agent is using.
- Run dev servers on separate ports and use separate local databases. If one
  local database has to be shared, agree on the board before re-seeding or
  migrating it.
- One owner per branch. Never push to the other agent's branch. Suggest
  changes as review comments instead.
- Branch from the latest `master`. Name the branch for the work
  (`redesign/hiring-job-page`, `fix/select-clipping`).
- If your slice must touch a file the other agent's open PR changes,
  especially shared ones like `src/app/globals.css` or `prisma/schema.prisma`,
  say so on the board first and agree who goes first.
- Stage files explicitly, never with `git add -A` or `git add .`. Never commit
  `.claude/*.local.json`, `.codex/`, `src/app/zz-preview/` or any `.env*` file.

## Pull requests and review

- The author opens the PR against `master`. Its body links the board claim and
  states the typecheck, lint and test results.
- Every slice gets an independent review before it is called done. This is
  `CLAUDE.md` rule 9:
  - **Codex's slices:** Claude's review on the PR is the rule-9 review.
  - **Claude's slices:** a separate Claude reviewer subagent reviews them, as
    today. Codex reviews them as well when Caden asks.
- The author fixes each finding, or says why not, and has the fix re-checked.
- Visual slices go to Astra with evidence: screenshots of the running app at
  phone and desktop widths, light and dark, plus a `manifest.json` of what
  was measured and the commit it was captured at.

## Talking on GitHub

Comments from the agents, Astra and Caden may all appear under Caden's
account. Keep them apart like this:

- Start every agent comment with its author and addressee in bold:
  `**Claude → Codex:** …`, `**Codex → Astra:** …`, `**Claude → Caden:** …`.
  Claims, releases and hand-overs on the board name only the author
  (`**Claude:** taking …`).
- End every agent comment with a footer line naming its author:
  `_Generated by Claude Code_` or `_Generated by Codex_`.
- When the agents disagree, neither argues it out in comments. Put both
  positions side by side for Caden in one comment and wait for Caden's call.

## Hand-offs

When an agent stops partway, it leaves a comment on the board covering:

- what's done;
- what's left;
- the branch and its last commit;
- anything the next agent must know (fixtures, local setup, open questions
  for Caden);
- the proposed new owner.

The branch stays with its owner until the new owner replies on the board with
`**<Agent>:** taking over <branch>` (or Caden reassigns it). Until then, the
other agent branches from the last commit instead of pushing to it.
