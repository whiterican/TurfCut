# 09 — Profile

**Route/source:** `/profile`, `ReadingPage`, `ProfileNav`, credential/availability/sharing/scorecard loaders; existing `/profile/*` routes. The current page leads with a masthead and extensive Scorecard/Experience content; the concept leads with identity and a simple menu.

**Order:** compact header/settings control → centered initials avatar, real name and permitted saved locality → actual credential/account/availability/payout setup menu rows → accessible links to work record, experience, sharing and preferences. Keep existing detailed records reachable through a section anchor or existing destination; do not delete them to make the first screen shorter.

**Geometry:** proposed 72px initials avatar, name H2, locality caption; 20px identity-to-menu gap; white divided rows, 44px minimum target, 20px icon, 10px gap, 14px padding; restrained status text on right. No 28/120 summary strip, star score or generic verification seal. Mobile Profile is reached through More in the current target.

**Data/replacements:** **Credentials** replaces unsupported identity/background-check/training claims; show verified/expired/pending only from the actual credential record and policy. **Availability** uses the saved availability; **Payout setup** uses actual Connect/account state; **Sharing & privacy** uses current choices and version warnings. No card digits or signed agreement fabricated from consent. Missing locality is omitted, never guessed.

**Exact new menu labels:** **Credentials**, **Availability**, **Payout setup**, **Work record**, **Experience**, **Sharing & privacy**, **Display settings**. Preserve existing labels inside each detailed workflow where they carry legal/state meaning. “Identity Verified” and “Background Check Completed” have no substitute checkmark.

**Acceptance:** no credentials, pending/verified/expired, setup incomplete, sharing re-consent required, empty/long name, availability unset, payout setup needed. Privacy warnings remain visible above optional content; record-sharing restrictions remain enforced server-side.
