# Additional screens: design and data contracts

Companion to [REVIEW.md](REVIEW.md), based on source at `d40b663`. These are proposed extensions of the founder's concept for screens not individually pictured. They are not newly approved mockups. Build within the existing Next/Tailwind/component system. Keep current loader/action contracts; no new schema or dependencies are implied.

## Shared visual grammar

Inherit current semantic tokens and `DARK_MODE.md`; use the token names already defined in `globals.css`, not per-page hex values. The board's light authority remains eggplant `#1C0F2E`, forest `#157A46`, cream `#FAF9F4`, white surface, muted `#E7E6ED`, border `#D7D2E0`, text `#0F172A`, subtle `#64748B`. The later mint active-dock exception stays. Inter: page heading 28/36 bold, section 20/28 semibold, row heading 16/24 semibold, body 16/24 regular, metadata 14/20, tertiary 12/16. Do not make essential instructions 12px to force a match.

Use the established 6/10/14/20/28 scale for new layout work, existing semantic radius/shadow tokens, restrained borders and surface differences. No new gradients, glass panels, giant rounded tiles, ornamental metric cards, emoji icons, arbitrary accent colors or invented universal scores. Photos belong to discovery/editorial content; operational forms and ledgers do not need stock photos. Keep initials when a real avatar is unavailable.

### Four different controls, four clear jobs

| Control | Behavior | Appearance |
|---|---|---|
| Primary worker navigation | Route navigation, current route via `aria-current` | Existing floating eggplant dock, six current destinations; light inactive, mint active icon/text, no active tile. More exposes secondary destinations. |
| Page state tabs | Upcoming/Past or equivalent mutually exclusive views; preserve URL/back behavior | One compact shared track, active eggplant segment in light mode, quiet inactive segments. If links navigate, use link semantics; do not add ARIA tab roles without tab keyboard behavior. |
| Filters | Job/category/status queries, counts only from actual scope | Quiet compact controls aligned with the list toolbar. Selected state plus readable label; horizontally scroll if needed, with visible focus and reachable final option. Do not shrink touch targets to fit. |
| Status | Read-only current state | Small semantic badge plus text. Never style as an interactive tab; color is supplementary. |

Keep payment-state filters visually grouped and subordinate to the queue. Do not make every status a large pill scattered over multiple lines when a compact labelled selector works better at 320px. Do not change the current default queue without an explicit product reason; an empty chosen queue can link to an existing nonempty queue.

## Exact empty/error copy proposals

Use these only for the stated condition. Preserve more specific existing actionable backend errors; do not collapse authorization, unavailable data and an empty result into one screen.

| Condition | Copy | Action |
|---|---|---|
| No matching filter results | “No results match these filters.” | “Clear filters” |
| No pending member invites | “No invitations waiting.” | Keep “Invite someone” form above |
| Worker has zero credentials | “No credentials added.” | Worker view: “Add a credential”; organizer view: no invented action |
| Worker withholds credentials | “This worker hasn’t shared credentials with your organization.” | No verification/proof action |
| No shifts for selected date | “No shifts scheduled for this date.” | Existing date controls |
| No payable items in selected queue | “Nothing ready to pay.” | Keep other queue controls; use only for Ready to pay, not To approve |

| Empty review queue | “No shifts waiting for review.” | Existing field/date navigation |

| Generic recoverable save failure | “Your changes weren’t saved. Try again.” | Preserve entered values and enabled retry |

## Per-family delivery checklist for Claude

Choose one family at a time under the existing milestone agreement. Use its existing source as the data contract. Before styling, list real action/state variants and permission differences. Preserve actions and accessible names through the change. Render one populated and one exceptional state at 390 and 1440, light/dark; include the additional states listed above when behavior differs. Capture against a commit or reproducible worktree patch, with route, role, fixture, time, timezone, CSS viewport, 2x scale, font readiness and repository-relative path. Do not publish personal production data in screenshots.

For unpictured screens, provide a same-size static design comparison or reference HTML when needed to settle layout before implementing the family; use the shared token names and no alternate application stack. Do not claim the composite is a pixel-exact per-route spec. The founder should review any meaningful new layout decision, while routine reuse of the approved pattern does not require a new redesign milestone.

Run typecheck/tests/lint and focused behavior checks. A separate Claude reviewer must check the slice under CLAUDE.md. In the handoff, name remaining states or blocked data honestly rather than marking the whole family complete because a wrapper or screenshot exists.
