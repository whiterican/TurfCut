# 03 — Job details

**Route/source:** `/jobs/[jobId]`, `RecordPage`, `WorkerPanel`, `JobFacts`, existing apply/offer/shift helpers. Existing authorization and job-card disclosures remain mandatory.

**Order:** photographic header with back/save/share controls → white title/pay region → organization and scoped verification → date/time, location, staffing facts → type/setting chips → **About This Job** → actual requirements → prominent application/status action. Primary action precedes the long secondary/legal record on mobile, as current work already supports. At desktop, image/main facts plus a restrained action column; full-width workspace for organization view stays role-appropriate.

**Geometry:** proposed 200px media height at 390px; 44px overlay control targets; 14px content padding; title H2, pay H3; fact rows 20px icon + 10px gap; no serif title or giant hero number. Main CTA is full-width Forest, at least 44px, unobscured by dock. A sticky CTA must account for the dock/keyboard; do not create stacked floating bars covering the content.

**Copy/data:** **Apply for This Job** only when eligible and not already engaged. APPLIED → **Application submitted**, retain existing withdrawal/status actions. OFFERED/INVITED → real accept/decline actions and deadlines. ACTIVE/CLAIMED → **You’re hired**, **View schedule** and existing shift choices. Hired without scheduled shifts retains the current truthful explanatory copy. Closed/expired/blocked states keep reasons. Job compensation, organization approval and campaign verification are separate fields; no fake bonuses, checkmarks or remaining-seat claim.

**States/evidence:** apply, applied, offered, invited, hired-with-shift, hired-no-shift, closed/paused, eligibility blocker, unknown rate, absent media, server failure. Verify repeat application prevention and the original server actions, not a new client-only state machine. The reference's sample $22/hr is fixture data only.
